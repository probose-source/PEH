# Insight Reel Studio (v1.4)

One insight in, one posted vertical Reel out, for any brand. Built from the Precision Equine Health "Precision Point" pipeline (PP001 v3.2 and PP003 v1.0, posted 2026-10-24), generalized. Runs interactively or unattended (scheduled); unattended mode never stops to ask and posts automatically.

v1.4 changes (Pro's review of PP001–PP003): footage must live in the subject's world and be literally true to the topic, no clip reuse across episodes (clip log), every episode must look different (rotating visual recipe), Pinterest is part of the posting path, and an episode log owns the numbering.

## 0. Modes
- Interactive: the user is present; follow every step.
- Unattended (scheduled run, or the prompt says "unattended"/"autopost"): never ask questions, never wait for approval; decide, note decisions in the episode log, and post when the build passes step 8 checks. If any required step fails (no insight scores 10+, voice-over, upload or posting fails), stop and report the reason in one push notification; never post a partial Reel.
- Session prerequisites (both modes): the posting-copy GitHub repo attached (`add_repo` with push, then `git clone --depth 1`); claude.ai Settings → Capabilities must allow `hook.us2.make.com` (chunked upload) and `pexels.com`, `videos.pexels.com`, `images.pexels.com` (stock). If a required host is refused, stop and say which one. Connector tool permissions for Make and Google Drive should be "Always allow" so unattended runs never wait on an approval.

## 1. Load the brand profile (ask once, then reuse)
Look for a brand profile in the user's Project docs or memory (`brand-profiles/<brand>.md`), or in the scheduled task prompt. If none exists and the user is present, ask one question at a time and save the answers there:
- Brand name, series name and numbering (e.g. "PRECISION POINT · No. 001"); the episode log doc that owns the numbering (§8)
- Audience, their age range (drives text size, §6) and insider vocabulary; any terminology glossary skill to load (e.g. peh-equine-glossary)
- Palette (background, accent, data color), display font file, logo file (current version only; retire old logo files from every build)
- Voice: ElevenLabs voice IDs and Make connection, or "user supplies MP3"; the brand's banned voices (never used, whatever the format); for dialogue, two characters (owner + sage), one voice and one accent color each. Character names are production labels only: they never appear on screen or in captions.
- Standing tagline and the standing CTA (e.g. "That was a little snack. For the full meal, join the <Brand> group.")
- Compliance limits (claims, regulated terms, required caption disclaimer) and subject-welfare rules (§5)
- Footage: the brand's own-footage Drive folder, the humor-clip Drive folder, the subject's world (where footage must live, e.g. barn, arena, paddock, feed room, wash rack, trailer), where finished files go, and the public GitHub repo that hosts posting copies and landing pages
- Posting: Make scenario IDs, Pinterest board and landing-page URL pattern (see "PEH defaults" below)

## 2. Pick and verify the insight
- Source: the user's digest, a pasted study, or a topic they name. Score Surprise, Relevance, Stakes, Concreteness, Evidence (0-3 each); proceed at 10+ with Evidence ≥ 1.
- Unattended: use the newest digest created in the last 24 hours; take the highest-scoring video-ready insight not already in the episode log (match on DOI). No new digest or no unused qualifying insight → stop and report.
- Episode number = the highest number in the episode log + 1, cross-checked against the brand's Facebook Page posts (Posts RPC) for a higher "No."; never reuse a number (PP002 was issued twice on 2026-10-24 before this rule).
- Every number must come from the source; publication name goes on screen in one short line, authors and year in the caption.

## 3. Write the script
Two formats (alternate them across the series):
- **Monologue** (30-45 s, ~95-115 words): Hook (≤8 words, provocative, in the subject's favor, never blaming the subject) → number by ~10 s → second proof → takeaway as an equation ("More X + more Y = less Z") → what to check (2-3 items) → honesty line → humor beat (only when an own clip is available, see step 5) → standing CTA.
- **Dialogue** (45-65 s, 12-16 lines): owner asks or confesses, sage answers with the number; crisp and funny, each line ≤ 15 words; one sage line is the quotable aphorism ("A tired horse is a polite horse"); the owner's last question sets up the humor clip; owner says the "little snack" line, sage gives the CTA.
Rules for both: personal ("Does your horse…?"), emotion before information, no on-air citations beyond the publication name, plain words plus precise glossary terms, never "it" for an animal, rotating closers so 1,000 posts don't repeat, no stale sign-offs (never "link in bio" unless asked), US English. Interactive: show the script and get approval before voicing. Unattended: no approval; voice it directly.

## 4. Voice-over
- Monologue: run the Make voice-over scenario (`scenarios_run`, responsive true) with `text`, `filename` (`<SERIES><NNN>_<slug>_VO_vX.Y.mp3`), `voice_id` and `model_id` → Drive, returns `drive_file_id`. Use the brand's required model (PEH: eleven_v4 only).
- Dialogue: one call per line (`<SERIES><NNN>vX_line{NN}.mp3`) with the owner and sage voices; bracketed emotion tags (`[amused]`, `[deadpan]`) where the model supports them.
- Voice rotation: vary the narrator across episodes from the brand's approved list and record the voice in the episode log; never use a banned voice. Direct the read to be animated, not newsreader-flat.
- Download with the Drive connector; results land in tool-result files or inline — base64-decode either (inline ones are recoverable from the session transcript).
- Timing: monologue `silencedetect` (n=-35dB, d=0.35) for sentence windows, then n=-32dB, d=0.15 inside long sentences for clause breaks; dialogue `silenceremove` both ends of each line at -40 dB, lines 0.4-0.7 s apart, ~2.5 s before the punchline so it lands on the humor clip's payoff. Karaoke chunk boundaries sit on detected pauses, never on character-count interpolation alone.

## 5. Footage: in the subject's world, true to the topic, never reused
- Layout (Mad Barn-style, validated against their top Reels): full-bleed footage; title tag top-left in tiers (hook split onto two lines if one line would exceed ~900 px, series pill under it); data callouts mid-frame; karaoke captions lower third; persistent logo + short tagline on a soft scrim. No speaker pills or names. Only the end card is a full-frame graphic.
- **Stay in the subject's world.** Every shot shows the brand's subject or its real environment (PEH: horses, barns, feed rooms, arenas, paddocks, wash racks, trailers, hands on a horse). Generic human-world stock (labs, pharmacies, kitchens, offices, people at tables) is allowed for at most ONE shot per Reel, and only when the line is literally about that place (a lab result → a lab bench, once). Never let a non-subject shot carry the hook, the main number or the CTA.
- **Literal truth test for props.** A prop on screen must be what the subject actually uses: an equine probiotic is a tub, bucket or pouch of powder or pellets and a scoop in a feed room — never pharmacy bottles, capsules, pills or dropper vials; a supplement "label" is a tub label; a hay net is a hay net. If no literal clip exists, show the subject (the horse eating, the feed room, the scoop) and let the callout carry the object, or build the object as a simple branded graphic (e.g. 11 plain tubs as outlined shapes). Wrong-world props read as AI filler and break trust.
- Source order: (1) the brand's own footage (Drive folder; prefer it for the hook and the humor beat); (2) free stock (Pexels via `vidiq_generate_broll`, portrait, commercial license, credit photographers in the caption); (3) a branded motion graphic for a gap. Never AI video for data-bearing motion.
- Search discipline: 3+ distinct queries per beat (the subject + the exact action: "horse eating from bucket", "feed room scoop grain", "groom pouring supplement horse"), each at minDurationSeconds 5. Pull from at least 3 different photographers per Reel and at least 2 clips the brand has never used.
- **Clip log and no-reuse rule.** The brand's episode log keeps a `footage:` line per episode (Pexels id or own-file name per shot). A clip used in any of the previous 8 episodes is off-limits except the brand's own signature footage (which may recur at most once every 4 episodes). A photographer's series (e.g. Barbara Olsen's barn set) counts as one source: at most 2 clips from one series per Reel and not in consecutive episodes. Before cutting, diff the shot list against the log and replace repeats.
- Stock downloads: direct from the workspace when the Pexels hosts are allowed; otherwise pass each clip's direct file URL to the Make "Fetch B-roll to Drive" scenario (`url`, `filename`, `folder_id`) and download the returned `drive_file_id` with the Drive connector.
- **Subject welfare (global rule):** never show the animal in distress, pain, fear or agitation (head shaking, pinned ears, wide eyes, bolting, flailing, thrashing) unless the topic itself is that behavior. The audience loves the animal; one distressed frame overrides every other message. Pull a contact sheet of 3+ frames per clip and reject any clip with one such frame; prefer calm, curious, eating, walking or affectionate footage.
- Always choose by looking at the contact sheet, then trim-in to the best moment. Slightly dim/desaturate footage (eq brightness -0.03, saturation 0.95) for text legibility.
- **Rotating visual recipe (so episodes don't look alike).** Each episode picks a different combination, recorded in the log, and no two consecutive episodes share the same hook treatment or end-card background:
  - Hook treatment: freeze frame on a key moment · slow motion (0.5x) · speed ramp (0.5x → 1.6x) · hard cut on the beat · match cut (object → subject)
  - Callout style: big number on scrim · counting tally (tubs/ticks appearing one by one) · arrow equation · split bar comparison · circled detail on a freeze
  - End card: blurred still of the episode's last shot · plain brand field · the brand's signature still
  - Shot count: 8-12 shots for a 45-50 s Reel, cadence varying between 3 and 6 s; at least one shot must move the camera or the subject, and one must be a close detail (eye, muzzle, hoof, hand on the horse).
- Humor beat is optional: list the brand's humor-clip Drive folder; if it holds an unused clip that fits the topic (check the episode log), use it with native audio muted and the voice-over gap timed so the punchline lands on the payoff frame. If there is no clip, drop the humor beat and its script line; never substitute AI or stock for it.

## 6. On-screen text rules (global feedback from PP001 v2.0 and v3.0)
- Legibility for a 50-70-year-old audience: **no text on screen under 56 px at 1080×1920, anywhere** — tagline, series pill, source line and callout sub-lines included. Captions 94 px, callout headline 110-190 px, callout sub-line ≥ 64 px, title tiers ≥ 60 px, end card body ≥ 68 px. If a line would need to be smaller to fit, shorten or split it instead.
- Karaoke, not subtitles: 2-5 words on screen at a time, never a full sentence; one phrase replaces the next in sync with the voice; the key word in the accent color (one accent per speaker in dialogue). Non-final chunks end exactly when the next begins (no overlap, or captions double up); only the last chunk of a line holds +0.12 s.
- One text element on screen at a time besides the title tag: a data callout or checklist replaces both the caption and the logo scrim while it is up (hide the scrim under full-width graphics).
- Punctuated graphics: each beat gets one strong visual hit (big number, arrow equation, checklist ticks) that appears with a hard cut and holds 2-4 s; no paragraphs; one short source line (≥ 56 px) under a callout at most.
- Keep all text out of the top 250 px and bottom 400 px; nothing may touch the right edge (check the title tag width); change something on screen every 3-5 s.

## 7. Assemble (ffmpeg, local)
- Each segment encoded separately to 1080×1920, 30 fps, yuv420p with explicit `-t` (never zoompan on looped stills); freeze = one extracted frame looped; slow-mo = `setpts=PTS/rate` with source `-t = dur*rate`; join with the concat *filter*, not stream copy.
- Overlays as transparent PNGs with `enable='between(t,a,b-0.04)'`.
- Audio: monologue voice-over with any gap; dialogue lines each `adelay`ed to their start and `amix`ed (normalize=0); music bed looped (`-stream_loop -1`) at ~0.11-0.12 with a 2 s fade-out, AAC; optional bed from ElevenLabs `createMusic` (instrumental). Rotate beds across episodes when more than one exists.
- Master at CRF 19; posting copy at CRF 27-28 (<30 MB, `-movflags +faststart`, H.264 high profile, closed GOP, AAC ≤ 128k). Filename `<SERIES><NNN>_<slug>_vX.Y.mp4` with a build stamp in the script and in the MP4 comment metadata.
- Pinterest cut: 16-18 s 9:16 — hook through the first data callout, then 2.5 s of the end card with an audio fade; `<file>_pinterest.mp4`.
- Cover frame: pick it yourself — the hook freeze with the title tag visible (usually 0.5 s); extract it as `<file>_cover.jpg` and pass the same offset as `thumb_offset` (ms) when posting.

## 8. Check, deliver and post
- Contact sheet of ~20 frames; check every one: right footage per beat (in the subject's world, literal props, no distress frames), text size, one text element at a time, safe zones, nothing clipped at an edge, no doubled captions, no character names, no clip from the no-reuse window. Fix and rebuild before posting.
- Write platform captions yourself: IG/FB with hashtags, photographer credits and the disclaimer (IG ≤ 2,200 chars, ≤ 30 hashtags); Pinterest title + description (≤ 500 chars) + landing-page link; X ≤ 280 chars; the CTA link goes in the first comment on FB and IG, never in the caption body (Instagram never makes caption or comment links clickable, so the brand's bio must carry the link). Save `<file>_captions.md` and the cover beside the MP4 (SendUserFile).
- **Get the file to Drive (full quality):** the Drive connector cannot carry a video and the Make webhook caps at ~10 MB per request, so use the chunked-upload scenario: POST multipart `action=init, filename, size, folder` to its webhook → it returns the Drive resumable session URI; then POST each 8 MiB chunk as `action=chunk, uri, range="bytes a-b/total", file=@chunk` → 308 per chunk, 200 + file JSON (`id`) on the last. Verify `fileSize` with `get_file_metadata`. Upload the Pinterest cut the same way.
- **Hosting:** commit the posting copy, cover and Pinterest cut to the brand's public GitHub repo (`reels/`), create the landing page `docs/<series>/<NNN>/index.html` (copy the previous episode's layout: video from the raw GitHub URL, key numbers, takeaway, CTA button, caveat, footage credits) with its `cover.jpg`, add the episode to the top of `docs/index.html`, push to main, and verify the raw URLs return 200.
- **Facebook:** run the post scenario with `drive_file_id`, `title` (the hook), `fb_caption`, `ig_caption`, `post_instagram` = "no". Make's "Publish a Reel" step reports `Unsupported get request. Object with ID '<video_id>'` *after* the Reel is already published — treat that exact error as success; confirm with the Posts RPC (`facebook-pages` v6, rpc `Posts` with `__IMTCONN__` = the Facebook connection id and `page_id`), which returns `<page_id>_<post_id>` for the new post (allow a minute for processing). Any other error: `executions_get-detail`, fix once, retry once, then report.
- **Instagram:** never feed it the Facebook CDN copy. Run the Instagram-from-URL scenario with `video_url` = the raw.githubusercontent.com URL, `ig_caption`, `thumb_offset`. A real publish takes ~60 s; the media id is in the `debug_igreel_url_<id>.txt` the scenario writes to the assets folder. Confirm with the IG media-check scenario: its `debug_igmedia_<id>.txt` must show `type=REELS` with a permalink; `(#100) nonexisting field (caption)` means an unpublished container — report, do not re-run blindly.
- **Pinterest:** run the video-Pin scenario with the Pinterest cut's `drive_file_id`, `cover_url` (raw GitHub cover jpg), `board_id`, `title`, `description` and `link` = the episode's landing page; the pin id is in `debug_pin_<id>.txt`. Pinterest search indexes new accounts slowly; verify at pinterest.com/pin/<id>.
- **First comments** (CTA link): Facebook by post id, Instagram by media id — never "latest post", which once hit an older post.
- Debug text files the read scenarios write to the assets folder: read, then trash.
- X is not auto-posted; include the X caption in the final message. The 9:16 file serves all platforms; make a 4:5 or 1:1 cut only if asked.
- **Episode log** (owns numbering): append one line to the brand's episode log — number, build stamp, topic, hook, DOI, format, voices, hook treatment / callout style / end card, `footage:` list (Pexels ids or own-file names), humor clip, FB post id, IG media id + permalink, Pinterest pin id, date.
- If Make reports the Facebook connection expired (PEH token expires 2026-12-23), stop and tell the user to reauthorize it in Make.
